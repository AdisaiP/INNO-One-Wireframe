Action placement contract

Action placement follows page type; do not move Save/Create/Schedule between header, section and footer on a page-by-page basis.

Overview / ListNew/Create belongs in Page Header. Filters, Columns and Export belong to the table toolbar.
Resource DetailResource operations belong in Resource Actions next to the resource identity.
Create / Edit / SettingsCancel/Discard and Save/Create/Schedule belong in the owning INNOActionFooter.
Builder / WizardNavigation or Run/Save actions remain in the owning builder/wizard footer.

State usage rules

LoadingUse skeletons when the final layout is known. Avoid blocking the whole page if only one panel is refreshing.
EmptyNo data exists yet. Explain what belongs here and give one useful next action when possible.
No ResultsData exists, but current search/filter matched nothing. Preserve search and offer clear/reset.
ErrorSay what failed, preserve user input, and offer Retry when retry is meaningful.
No PermissionDo not expose restricted data. Explain access requirement without implying the module is broken.
OfflineKeep cached/read-only information visible when possible; disable only actions that require live connectivity.
Disabled ModuleShow organization-level availability separately from user permission.
Partial FailureNever collapse mixed results into “Failed”. Show succeeded / failed counts and retry only failed items.

Interaction standards

Shared behavior for menus, filters, confirmation, columns, toast, tabs and keyboard dismissal.

Standardized
One interaction language across every app.
ESC closes menus, drawers and dialogs. Arrow keys move between tabs. Destructive actions always require confirmation.

Context menu

Use for low-frequency row or resource actions. Never place the primary action here.

Filter drawer

Use when filters exceed two simple selects. Applied filters stay separate from search.

Column selector

Use the same anchored checklist pattern for all dense operational tables.

Destructive confirmation

Required before delete, stop process/service, shutdown, remove or other irreversible actions.

Toast feedback

For non-blocking results after save, copy, assignment or queued actions.

Keyboard behavior

ESC dismisses overlays. Tab focus returns to the triggering control. Left/Right arrows navigate tabs.

Esc · Dismiss← → · Tabs⌘ K · Global Search

Pattern selection rules

Context Menu2–6 secondary actions tied to one row or resource.
Confirm DialogDestructive or high-impact state changes: delete, stop, shutdown, remove.
Drawer / SheetContextual edit or filter flow with roughly 3–8 fields while preserving page context.
Full PageLarge creation flows, multi-section forms or workflows needing their own URL.
ToastNon-blocking confirmation. Do not use toast for errors requiring user correction.

Usage rules

NavigationKeep the same icon for the same destination across Rail, Sidebar and launcher surfaces.
ActionsUse icon + label for primary/secondary actions. Icon-only controls are reserved for universally understood compact actions such as More, Close or Back.
AccessibilityDecorative icons are aria-hidden. Every icon-only interactive control must expose an aria-label or title.
BrandsBrand icons are used only for real brands such as Chrome. Hardware concepts such as USB use normal product icons, not the Brands set.
React migrationConsume semantic tokens, not Font Awesome class names. Lucide becomes the implementation library while the meaning stays unchanged.
SizeRail 15px · Sidebar 13px · Buttons 11px · Header controls 13px · Resource icon 17px.
